1-2. 이 질문서가 필요한 이유

출처 질문서 §1

사료편찬위원회는 『정토대전』 4권 세트(책정가 200,000원, 확정 여부는 Q06)를 외부 서점에 내지 않고 정토회원에게만 판매하려 하며, 시스템국에 두 가지 검토를 맡겼습니다. 하나는 회원인증을 거친 판매 경로를 만들 수 있는지, 다른 하나는 e북을 자체로 만들 수 있는지(기술 가능성, 범위·인력·기간, 현 인력으로 감당할 수 있는지)입니다. 시스템국의 현재 초안은 종이책을 먼저 마이정토 임시 구매 메뉴와 카드결제·PG 가상계좌(PG는 결제대행사)로 판매하고(약 2~3주, 10~18인일), e북은 자체 웹 뷰어로 나중에 여는 것(최소 10주, 66~121인일)입니다. 이 초안은 현업이 아직 답하지 않은 내용을 시스템국이 임시로 가정해 세운 것입니다. 시스템국은 이 문서의 답을 받아 개발 범위, 투입 인력, 기간을 확정하고, 현 인력으로 이 일을 맡을 수 있는지(수용 여부)를 판단합니다.

초기 검토보고서는 5대 질문 회신을 10/12까지, 결제대행사 계약·계정 확인을 10/14까지 받고 10/15 개발담당 회의에서 종이책 판매 수용과 공수를 확정하는 일정이었습니다. 오늘(2026-10-19) 기준으로 이 기한은 모두 지났고, 회신이나 회의 결과는 문서에 기록되어 있지 않습니다. 답이 늦어지면 출간·판매 일정도 그만큼 밀립니다. e북의 '최소 10주'에는 첫 1~2주의 요구사항 확정과 원고 인수가 들어 있고, 결제대행사 가맹 심사에도 최소 1~2주가 걸리기 때문입니다(검토보고서 §4.2). 또 기존 문서는 마이정토의 기존 결제 기능과 '신청 후 결제' 화면 흐름을 재활용한다고 보고 종이책 판매 일정을 잡았습니다. 그런데 시스템국이 마이정토 프로그램을 직접 확인해 보니 결제대행사 연동, 결제 단계가 있는 신청 흐름, 관리자용 엑셀 내려받기 기능이 없었습니다. 로그인 수단은 Google 계정 하나뿐이고, 마이정토 메뉴는 전법회원·발심행자에게만 보입니다(시스템국 코드 확인, 원천 문서 외). 그래서 종이책 판매 일정(2~3주)과 판매 대상 관련 작업량은 다시 산정해야 하며, 늘어날 수 있습니다(전제 A06).

질문은 언제까지 답이 필요한지에 따라 세 단계로 나눴습니다. 선택지가 있는 질문은 고르시는 쪽에 따라 무엇이 달라지는지 함께 적었습니다. 문장 끝의 표시는 다음 뜻입니다. '(법무 확인 필요)'는 법령 해석이 걸려 있어 단정하지 않은 부분, '(시스템국 코드 확인, 원천 문서 외)'는 기존 문서가 아니라 시스템국이 마이정토 프로그램을 직접 확인한 내용, '(해석)'은 시스템국의 추정, '문서에 없음'은 기존 문서에 값이 없다는 뜻입니다. 숫자를 적어 주셔야 하는 자리는 '( )'로 비워 두었습니다.

1-6. 답하는 순서

출처 질문서 §1
  1. Q01에서 현업 대표 창구와 부문별 승인자를 먼저 정해 주십시오. 이후 질문의 답은 이 창구로 모아 회신해 주시면 됩니다.
  2. Q06에서 e북 상품 구성과 세트 가격을 정합니다. '④ 이번에는 e북을 내지 않음'을 고르시면 e북 전용 질문(Q14~Q22, Q25, Q36~Q55, Q57)은 답하지 않으셔도 됩니다. 단, Q56(장애·다른 회원 정보 노출 사고 공지)은 종이책 판매에도 필요하므로 꼭 답해 주십시오.
  3. Q06에서 ①(종이책 세트에 e북 무료 부속)을 고르셨다면 Q25(종이책 판매 때 e북 조건 안내)와 Q49(종이책 구매자 e북 부여 기준)도 정합니다. ②·③·④를 고르셨다면 두 질문은 답하지 않으셔도 됩니다.
  4. e북을 내기로 하셨다면 Q14(제공 형태)와 Q16(유출 방지 방식·예산)을 정합니다. Q16에서 상용 솔루션을 고르셨다면 Q42(업체 계약 조건)도 정합니다.
  5. Q08에서 결제 수단을 정합니다. 가상계좌를 받기로 하셨다면 Q26(계좌·입금 안내 발송 수단)도 정합니다.
  6. Q12에서 환불 원칙을 정합니다. 'e북 열람 후 환불 제한'을 고르셨다면 Q44(세트 일부 열람 시 환불)와 Q45 가·나(환불 제한 안내 문구와 열람 시작 기준)를 정합니다. Q45 다, Q46(구매 전 미리보기), Q47(환불 심사 중 열람 보류)은 환불 정책과 관계없이 e북을 내면 답해 주십시오.

왜 필요한가

판매 대금은 기부금 영수증 대상과 섞으면 안 됩니다. 새로 계약하면 가맹·카드사 심사에만 최소 1~2주가 걸려 판매 시작일이 밀릴 수 있고, 결제대행사가 정해져야 결제 개발을 마칠 수 있습니다. 기획 문서는 마이정토에 기존 결제(보시금·기도비)가 있다고 보고 그 재사용 여부를 물었지만(02 §2.2 #1), 마이정토에는 결제대행사 연동이 없습니다(시스템국 코드 확인, 원천 문서 외).

  • 도서 판매 전용 결제 계정 신규 계약 → 최소 1~2주의 가맹 심사가 종이책 판매 일정의 선행 조건이 됨

03 §5.2와 01 §3 Q2는 3일을 정해진 값처럼 적었고, 02 §2.3의 '필수 기획 디테일 1'('주문 후 3일(72시간) 이내 미입금 시 자동 만료·취소')과 검토보고서 §3.2-2('주문 후 3일 이내 미입금 시 자동 취소')도 같습니다. 반면 같은 02 §2.3의 비교표와 01 B-2 #5는 '예: 3일', 검토보고서 §6은 '입금 기한 3일 등'으로 예시처럼 적었고, 01 D5 확정서는 '__일'로 비어 있습니다.

6. 기존 결제 전제 코드 대조

02 §2.1·§2.2는 마이정토에 기존 결제(보시금·기도비)와 '기도 접수·수련 신청' 흐름이 있다고 보고 그 흐름의 차용과 결제 계정 분리 여부를 다룹니다. 검토보고서 §2.1도 같은 흐름의 차용을 제안했고, §4.1은 '기존 결제 코드가 있다면' 복사해 쓸 수 있다고 조건부로 적었습니다. 그러나 마이정토에는 결제대행사 연동과 결제 단계가 있는 신청 흐름이 없습니다(시스템국 코드 확인, 원천 문서 외).

7. 판매 대상 코드 대조

01 D3 초안은 '마이정토 로그인 회원 전체'입니다. 그러나 마이정토 메뉴는 전법회원·발심행자에게만 보이고, 01 B-1 #1이 쓰는 '정토행자'·'모둠원'은 마이정토 프로그램의 회원 구분에 없는 용어입니다(시스템국 코드 확인, 원천 문서 외). 판매 대상을 가리키는 말도 README §1은 '정토회원', 01 B-1 #1은 '전체 마이정토 가입 회원', 검토보고서 §5는 '전체 정토회원', 01 D3는 '마이정토 로그인 회원 전체'로 서로 다르게 적었습니다.

8. CS 계정 혼동 가정 코드 대조

04 §3.2①은 '카카오 로그인 계정과 일반 아이디 계정 혼동'을 가정하지만, 마이정토의 로그인 수단은 Google 계정 하나뿐입니다(시스템국 코드 확인, 원천 문서 외).

9. 판매가

01 D3에는 '200,000원'이 미리 적혀 있고 03 §4.1·§5.1은 200,000원을 결제 금액 검증 기준값으로 고정했지만, 실행매뉴얼 §4.4는 이 금액을 확정 가격으로 취급하지 않습니다.

10. 환불 기준과 기간 시작일

7일 자체는 실행매뉴얼 §4.2가 일반 청약철회 기준(계약서면 수령·공급 시점)으로 언급한 값입니다(법무 확인 필요). 그러나 01 D5는 '첫 열람 전 7일 이내'라는 조건을 붙였고, 04 §3.3은 '결제일로부터 7일', 실행매뉴얼 §4.2는 '계약서면 수령·공급 시점 기준'(법무 판단 대상)으로 기간을 세는 시작일이 서로 다릅니다.

11. 종이책 구매자 e북 부여

README §1, 02 §1.1, 03 §5.3·W21, 04 §2.2-7은 종이책 구매자에게 e북을 일괄 부여한다고 전제하지만, 01 B-1 #2와 실행매뉴얼 §2.1은 미결로 두었고 02 §3.1 P0는 판매 공지에 e북 약속 문구를 넣지 말라고 합니다.

12. 복제 차단 수준 설명

01 §1.2('완전 차단이면 P4·P5 필수'), 01 §3 Q4('100%에 가까운 DRM'), README('철통 보안 시 P4')는 P4·P5로 완전 차단이 되는 것처럼 적었습니다. 그러나 실행매뉴얼 §20.4는 P5도 외부 카메라까지 막는 보장은 아니라고 적었고, P4에 대해서는 §20.3이 '제품이 실제로 보장하는 수준으로 검증'하라고만 적어 보장 범위가 확인되지 않았습니다. 02 §3.2의 1순위 업체는 브라우저 기반 웹 뷰어입니다.

13. P2 '0원'

02 §1.1과 README §1의 '예산 0원', '솔루션 비용 0원'은 라이선스 비용만 뜻하며, 개발 인력, 월 운영비(03 §7.2), 결제 수수료는 별도로 듭니다. 수수료는 02 §2.3 무통장 입금 비교 칸에 'PG 건당 수수료 약 200~300원', 검토보고서 §3에 '건당 수백 원'으로만 적혀 있습니다. 가상계좌 수수료는 '건당 소액'이라고만 되어 있어 실제 계약 요율은 정해지지 않았습니다.

14. 작업량과 기간

README §1·02 §1.1은 '최소 10주(66~121인일)', 03 §7.1은 '개발자 2명 기준 약 10주'로 적었지만, 실행매뉴얼 §21.2는 10주·2명의 명목 투입이 약 100인일이라 121인일 상한이면 기간이나 인력을 조정해야 한다고 적었습니다. 뷰어 개발 메모의 '2~3일'은 뷰어 화면만 계산한 값으로 보입니다(해석).

15. P4 일정

02 §3.2 ② 도식은 '개발 2~3주로 단축'이라고 했지만, 같은 절 TIP은 마이정토 로그인 연동 어댑터(약 2~3주)와 실제 원고 시험이 별도로 필요하다고 적었습니다. 실행매뉴얼 §20.3은 계약·심사 기간을 업체 회신으로 확정하며 확정 납기처럼 쓰지 말라고 적었습니다. 조달·계약을 포함한 전체 기간은 문서에 없습니다.

16. P2/P4 결정 시점

README §4는 G2 기술 검증 뒤 최종 결정이고 01 D1은 G0 확정서 항목입니다. 03 §7.4는 착수 5일차에 결정하면서 실제 원고가 없으면 가짜 PDF로 진행하도록 해, '대표 원고로 한자 검색 확인'이라는 G2 조건과 충돌합니다.

17. 원고 완성 전제

02 §3.2 ①·③은 4권 인쇄 조판 PDF가 이미 완성된 것으로 적었지만, 01 B-5 #16은 원본 형식을 아직 묻고 있고 D6 인도일은 비어 있습니다. 01 §1.2의 '검색 완벽 가능'도 같은 문서 §4.2와 실행매뉴얼 §5.2의 '문자 매핑 오류 시 검색 깨짐'과 어긋납니다.

18. 워터마크 표시 내용

검토보고서 §5는 회원ID, README §2는 회원 식별코드, 뷰어 개발 메모는 법명/이름, 01 §5.4와 02 REQ-SEC-01은 열람코드(JT-xxxx)로 적었습니다.

03·04 문서가 전제한 서버·저장소 구성과 로그인 연동 방식은 현행 마이정토 운영 환경과 다릅니다. 시스템국이 내부에서 다시 맞춰 산정하며, 그 결과는 월 운영비 상한(Q52)에 반영합니다(시스템국 확인, 원천 문서 외).

02 §2.3은 카카오 알림톡 발송을 전제로 하지만 마이정토에는 알림톡 연동이 없습니다. 기존 발송 수단은 정토회 문자 발송 시스템, 이메일, 마이정토 내부 메시지입니다(시스템국 코드 확인, 원천 문서 외).

21. 기능·데이터 구조 불일치

03 책갈피 기능에는 '메모'가 있고 04 §6.2 종료 절차에는 '메모 반환'이 있지만, 01 D4와 03 §7.1 산정 전제는 메모 제외입니다. 03 열람권 설계에는 선물로 받은 열람권과 일시 정지 상태가 빠져 있어, 03 §5.2의 '별도 선물권' 언급, 실행매뉴얼 §10.3과 다릅니다. 시스템국이 내부에서 맞춥니다.

02 화면들은 '열람 기간'을 전제하고 03 열람권 설계에 만료일 항목(비어 있으면 무기한)이 있지만 값은 정해지지 않았습니다(D3 빈칸). 04 §3.2·§5.1은 '영구 열람권' 표현을 쓰고, 04 §6.1은 탈퇴 시 책갈피 즉시 파기를 확정했지만 실행매뉴얼 §4.3은 이를 미정으로 둡니다.

26. 승인 주체 범위

01 §6.1 요구사항 확정서 서명란은 사업(사료편찬위)·편집·기술·법무/개인정보·회계/정산·운영/CS 6개 부문을 모두 갖추고 있습니다. 04 §7.1 출시 승인서도 사업·편집·기술·법무·개인정보·회계·운영·CS 책임자 서명을 요구합니다. 그러나 README §4의 G5 승인 주체는 콘텐츠·기술·법무·회계, G6는 사업·기술·운영으로, 04 §7.1(G5에서 G6로 넘어가는 양식)과 부문 구성이 서로 다릅니다. 종이책 판매 오픈의 승인 절차와 승인자는 어느 문서에도 없습니다.

04 §7.1 점검 항목 5·13은 '면세 설정'과 'ISBN 발급 완료'를 전제하지만, 01 D8은 전자책 ISBN 발급 여부를 미정으로 두었고 실행매뉴얼 §4.4는 ISBN만으로 면세를 자동 적용하지 않는다고 적었습니다(법무 확인 필요).

• 결제대행사(PG): 카드결제와 가상계좌 발급·입금 확인을 대신 처리해 주는 회사입니다. 정토회가 이 회사와 가맹 계약을 맺어야 판매 대금을 받을 수 있습니다.
